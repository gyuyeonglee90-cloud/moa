## 테스트 범위
1. **자동 검사**: `npm ci && npm run build && npm test` 결과
2. **핵심 시나리오** (로컬 `npm run preview`와 배포 URL 둘 다):
   - T1 첫 방문 → 온보딩 → 체험 시작 → 홈
   - T2 챌린지 A 인증(사진, 스탬프 각각) → 내 부위가 그려짐 → 히스토리 반영
   - T3 챌린지 B '다음 날로' → 완성식(목표 vs 우리) → 굿즈 가상 주문 예약 → 도감 등록
   - T4 새 챌린지 만들기 3단계 → 목표 캐릭터 → 부위 나누기 → 홈 노출
   - T5 흔적 경계값: 같은 부위 미인증 1/2/3/4회 → 크기·기울기·물결선이 PRD 5-3 표와 일치, 최대 2배 제한, 전원 인증 날의 반짝이
   - T6 새로고침 후 상태 유지 / '데모 초기화' 후 원상복구
   - T7 미인증 친구 콕 찌르기 토스트
3. **PRD 대조**: PRD v2 4장 포함 항목 9개가 각각 구현됐는지 체크
4. **반응형**: 360 / 390 / 768 / 1440px
5. **엣지 케이스**: 빈 메모, 아주 긴 이름(30자), 큰 사진(5MB+), 같은 날 중복 인증, 도감이 많아질 때
6. **접근성 (WCAG 2.2 AA, `docs/references/ux-quality-guidelines.md`)**: 대비(axe-core 자동 검사 + 직접 확인), 키보드만으로 투어 완주, 포커스 표시, 스크린 리더 라벨(캐릭터, 아이콘 버튼, 인증 상태), 터치 영역 44px, 글자 200% 확대, reduced-motion, 색만으로 상태를 표현하는 곳이 없는지
7. **가이드 투어 (PRD 8-1)**: 6단계 완주, 건너뛰기, 다시 보기, 투어 중 새로고침
8. **포트폴리오 관점**: 처음 보는 사람이 3분 안에 핵심 흐름을 이해하는지, README 링크와 스크린샷이 정상인지

브라우저 조작 도구가 있으면 사용하고, 없으면 Playwright를 임시로 설치해 스크린샷으로 검증한다(`docs/qa/screenshots/`).

## 추가 사항 (D21~D25)
- **제외된 범위는 결함으로 잡지 않는다**: S2는 안내 화면만, 사진 업로드 없음(스탬프 + 메모), 초기화 확인은 브라우저 기본 확인창(D25)
- **3D 캐릭터** 확인: 드래그하면 회전하고 관성 후 원위치로 돌아오는지, 몸통 탭 시 말랑한 반응, 부위 탭 시 그 부위만 흔들리고 담당자가 표시되는지(몸통이 같이 반응하면 버그), 포인터를 따라 기울어지는지. reduced-motion이나 WebGL이 꺼진 환경에서 정지 이미지로 대체되는지. 모바일 폭에서 드래그가 페이지 스크롤과 충돌하지 않는지
- 캐릭터 생김새는 아직 임시 도형이다. 모양 자체는 평가하지 않는다
- 포트폴리오용 스크린샷 3장 이상(투어 중 흔적이 생기는 순간, 완성식, 굿즈)을 `docs/qa/screenshots/`에 저장한다(README에 사용)
