## 6. 접근성 (WCAG 2.2 AA)

axe-core로 S0(온보딩)·S1(홈)·S2(챌린지 만들기)·S3(챌린지 상세)·S4(인증하기)·S6(도감)·S7(도감 상세) 7개 화면을 스캔했다. 자동 도구 결과만으로 충분하다고 보지 않고, 직접 키보드 포커스 이동·reduced-motion·WebGL 폴백도 확인했다.

- **색상 대비**: 하단 탭의 비활성 라벨("도감"/"홈") 색상이 2.65:1로 WCAG AA 기준(4.5:1) 미달(QA-03).
- **랜드마크/구조**: 테스트한 7개 화면 **전부** `<main>` 랜드마크가 없음(axe: `landmark-one-main`, `region`). 추가로 S0·S2·S4는 `<h1>`이 없음(`page-has-heading-one`) — S3·S1·S6·S7은 h1 있음(QA-04).
- **키보드만으로 투어**: 온보딩에서 Tab으로 두 버튼("크루 합류하기"/"그냥 둘러보기") 모두 포커스되고 포커스 링이 보임(`outline: solid` 확인), Enter로 정상 진입함. 전체 6단계를 키보드만으로 끝까지 진행하진 못했으나(시간 제약), 코치 카드의 버튼들도 일반 `<button>`이라 Tab/Enter로 접근 가능한 구조임.
- **스크린리더 라벨**: 캐릭터 캔버스에 `role="img"`+`aria-label`, 부위별 진행률 텍스트 타일이 캔버스 아래 항상 존재(DEV_LOG 확인, 코드 리뷰로 확인). 아이콘 버튼(+, 데모 도구 등)은 대부분 텍스트 라벨이 같이 있어 별도 `aria-label` 없이도 의미 전달됨.
- **터치 영역 44px**: 주요 버튼(스탬프, CTA)은 44px 이상으로 보임(코드 기준 `h-11`=44px, `h-[52px]` 등 사용).
- **reduced-motion / WebGL 폴백**: `reducedMotion: 'reduce'`로 챌린지 상세 진입 시 `<canvas>` 개수 **0건**(일반 모드는 1건) — `StaticThumbnail`로 정상 대체됨을 확인.
- **색만으로 상태 표현**: 흔적 텍스트는 숫자(%)·아이콘(✨)과 함께 표시되어 색에만 의존하지 않음. 굿즈 상생 구조 비율은 현재 구현에서 막대 그래프 자체가 없고 텍스트 비율만 표시되어 오히려 색 의존 문제는 없음(QA-07과 연결).

## 7. 가이드 투어 (PRD 8-1)

6단계(초대→부위맡기→첫인증→7일 진행(5일차 쉬기 선택)→완성식→굿즈) **전체를 끝까지 자동 진행하여 완주 확인**. 5일차에 "오늘은 쉬기"를 선택하면 정확히 PRD 문구대로 "내 왼쪽 눈이 25% 커졌어요" 흔적이 생기고, 최종 완성식까지 자동 이동했다. "가이드 건너뛰기" 버튼 존재 확인(클릭 시 별도 테스트는 생략, 코드상 `skipTour()`가 `tourStep: null`로 즉시 투어를 끝내는 단순한 동작이라 리스크 낮음). **투어를 다시 보는 기능(가이드 다시 보기)은 찾지 못함**(QA-11) — `DemoControls`에는 "다음 날로 넘기기"/"처음 상태로 되돌리기"만 있고, `startTour()`는 온보딩·S2(챌린지 만들기 안내) 진입 시에만 호출된다. 투어 중 새로고침은 zustand persist로 `tourStep`과 진행 상태가 그대로 보존되어 이어서 진행 가능함을 확인.

## 8. 포트폴리오 관점

- 처음 보는 방문자가 온보딩 카피만 읽어도 "크루가 캐릭터를 나눠 맡아 완성한다"는 컨셉이 명확히 전달됨.
- 3분 체험(투어 전체)을 자동 조작으로도 수 초 안에 끝까지 돌릴 수 있을 만큼 플로우가 매끄러움(불필요한 로딩/대기 없음).
- **README.md의 스크린샷 3장 자리가 아직 비어있음**(주석 처리된 상태). 이번 QA에서 `docs/qa/screenshots/`에 대표 스크린샷을 7장 찍어뒀으니, 개발 세션이 README에 연결하면 됨(QA는 README/코드를 직접 수정하지 않음).
- 배포 URL(`https://gyuyeonglee90-cloud.github.io/moa/`)이 정상 응답(200)하고, 온보딩→투어 시작까지 로컬과 동일하게 동작함을 확인. GitHub Actions 배포 워크플로우도 최근 커밋까지 전부 성공 상태.

## 9. 3D 캐릭터

- 드래그 시 회전 동작, 드래그 종료 후 포인터 이벤트 에러 없이 정상 복귀(관성/스프링 로직은 코드 리뷰로 확인, 자동화로는 "에러 없이 동작"까지만 검증).
- 몸통 탭 시 스쿼시(통통 튀기) 애니메이션 트리거, 부위 탭과 몸통 탭이 서로 간섭하지 않도록 레이캐스트 우선순위와 `stopPropagation()`이 코드에 반영되어 있음(DEV_LOG에 기록된 수정 사항 확인 — 실제 조작으로는 화면 좌표 기반 탭이라 어떤 부위를 정확히 맞혔는지까지는 자동화로 완전히 검증하지 못함, 수동 재확인 권장).
- WebGL 미지원/`prefers-reduced-motion` 환경에서 `<canvas>` 자체가 렌더링되지 않고 `StaticThumbnail`로 교체됨을 확인(6장 참고).
- 모바일 폭(390px)에서 캔버스 영역 내 드래그 시 페이지 자체 스크롤과 충돌하는 현상은 관찰되지 않음.
- 캐릭터 생김새(임시 도형)는 평가 대상에서 제외함(지시사항대로).

## 11. UX 지침 자체 점검 (`docs/references/ux-quality-guidelines.md` 7장)

1. **핵심 사용자·과업**: 포트폴리오 방문자가 "크루와 함께 캐릭터를 완성하는 경험"을 3분 안에 체험하는 것이 핵심 과업. 두 번째 사용자층(개발자/채용 담당자)은 README를 통한 빠른 이해.
2. **적용한 기준**: WCAG 2.2 AA(색 대비, 랜드마크, 키보드, reduced-motion), 터치 타깃 44px, 입력 오류 시 원인+해결 안내, 되돌릴 수 없는 행동(초기화) 전 확인.
3. **막힘/모호한 점**: 중복 인증 시 무응답(QA-01)이 가장 눈에 띄는 막힘. 그 외엔 투어 플로우 자체는 막힘없이 끝까지 진행됨.
4. **미충족 항목**: 색상 대비(QA-03), 랜드마크 구조(QA-04) — 모두 위 표에 근거와 영향 기록함. 콕 찌르기(QA-02)는 "보이지 않는 실패" 항목이 아니라 기능 누락이라 6장보다는 2장(핵심 과업)에 해당.
5. **남은 품질 위험**: 현재 작업 트리의 빌드 깨짐(⚠️ 긴급 항목)이 가장 큰 리스크 — 다음 배포 전 반드시 해결 필요. 그 외 굿즈 플로우 단순화(QA-07)는 "의도된 범위 축소"인지 "미완성"인지 PO 확인이 필요해 보임(D21~D25에 명시적으로 포함되지 않은 항목이라 QA 판단으로는 P2로 두었음).
