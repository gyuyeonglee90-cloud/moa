## 1. 색

### 1-1. 구조색 (UI)
| 토큰 | hex | 용도 | 대비 |
|---|---|---|---|
| `canvas` | `#F6F5F4` | 앱 기본 배경(따뜻한 종이) | — |
| `surface` | `#FFFFFF` | 카드, 시트, 입력칸 | — |
| `hairline` | `#E6E6E6` | 카드 테두리, 구분선(장식용) | 장식 |
| `ink` | `#000000` (본문은 `rgba(0,0,0,0.92)`) | 제목, 본문, **주요 버튼 배경** | 19.3:1 |
| `ink-2` | `#31302E` | 보조 본문 | 12.1:1 |
| `ink-3` | `#615D59` | 캡션, 메타, **플레이스홀더** | 6.0:1 (canvas) |
| `ink-4` | `#A39E98` | **비활성 상태 전용, 정보 글자에 사용 금지** | 2.4:1 ✗ |
| `field-border` | `#8A857F` | 입력칸·체크박스 테두리 | 3.7:1 (UI 3:1 충족) |
| `accent` | `#0075DE` | 링크, 포커스 링, 진행 게이지, 활성 탭 표시 | 4.6:1 (흰 배경만) |
| `accent-strong` | `#005BAB` | canvas 위 파란 글자, accent 눌림 상태 | ≥ 6:1 |
| `success` | `#137A2A` | '인증 완료' 아이콘과 글자 | 5.5:1 |
| `notice` | `#B45309` | '아직 인증 전' 아이콘과 글자 (빨강 금지 — D5) | 5.0:1 |

**보정 사항 (노션 원본 대비)**
- 노션의 `#A39E98`은 흰 배경 대비 2.7:1로 AA에 미달 → 비활성 표시에만 쓴다. 플레이스홀더는 `ink-3`을 쓰고, 입력칸에는 항상 보이는 라벨을 둔다.
- 노션 블루는 canvas(#F6F5F4) 위에서 4.2:1 → canvas 위 파란 글자는 `accent-strong`을 쓴다.
- 노션 sticker green `#1AAE39`은 2.9:1 → 상태 표시에는 `success #137A2A`를 쓴다.
- 노션 hairline은 1.25:1 → 입력칸처럼 '조작 가능한 경계'에는 `field-border`를 쓴다.

### 1-2. 주요 버튼 = 검정 (노션과 다르게 결정)
노션은 파란 버튼을 쓰지만, MOA의 주요 버튼(CTA)은 **검정 알약(`ink`)**으로 한다.
↳ 캐릭터가 6가지 색을 쓰기 때문에, 파란 버튼은 하늘색 캐릭터와 겹쳐서 묻힌다. 검정 버튼은 어떤 캐릭터 옆에서도 가장 분명하게 보이고, 레퍼런스 1·2 모두 검정 알약을 쓴다.
→ 파랑(`accent`)은 버튼에 쓰지 않는다. 링크, 포커스, 진행 게이지, 활성 표시처럼 **"지금 상태"를 알려주는 신호**에만 쓴다. 구조 역할을 하는 색은 검정과 파랑 두 가지뿐이고, 역할이 겹치지 않는다.

### 1-3. 캐릭터 팔레트 (장식 전용 — 노션 sticker 팔레트에서 파생)
캐릭터 몸통은 **방사형 그라데이션 3단(하이라이트 → 기본 → 그림자)**으로 칠한다. 캐릭터의 타일과 히어로 배경에는 `tint`를 쓴다.

| 키 | 이름 | light | base | deep | tint(타일 배경) |
|---|---|---|---|---|---|
| `lime` | 라임 | `#E4FBC9` | `#8FE05A` | `#3FB82E` | `#EEFBE0` |
| `pink` | 핑크 | `#FFE0F3` | `#FF9AD8` | `#FF64C8` | `#FFEEF8` |
| `coral` | 코랄 | `#FFE1DA` | `#FF8A7A` | `#F0503C` | `#FFEFEB` |
| `sky` | 하늘 | `#DDEEFF` | `#8CC4F5` | `#3D8FE0` | `#EAF4FF` |
| `sun` | 해바라기 | `#FFF3CC` | `#FFD36B` | `#FFAE1A` | `#FFF8E3` |
| `lavender` | 라벤더 | `#F2E8FD` | `#D6B6F6` | `#9B6FD6` | `#F6F0FE` |

- base 위의 검정 글자 대비는 6색 모두 9:1 이상 → 캐릭터 색 타일 위 글자는 항상 `ink`.
- **금지**: 캐릭터 색을 버튼, 구분선, 상태 표시에 쓰지 않는다(노션 원칙: 장식색으로 구조를 칠하지 않는다).

### 1-4. 히어로 배경
캐릭터 히어로(S0, S3, S5)는 `canvas`가 아니라 **위에서 아래로 흐르는 하늘빛 그라데이션** `#E3F1FF → #F7FAFF → #FFFFFF`을 쓴다. 해당 캐릭터의 `tint`를 10% 섞어도 된다. 이 그라데이션은 앱 안에서 유일하게 배경에 색이 들어가는 영역이다(노션의 "단 하나의 히어로 밴드" 원칙을 낮 버전으로 적용).

## 2. 타이포그래피
- **폰트**: Pretendard Variable(한글과 라틴 모두, Inter와 비슷한 비율). 숫자에는 `font-variant-numeric: tabular-nums`.
- **워드마크 "moa"**: 레퍼런스 1처럼 소문자, 아주 굵게(Pretendard 900), 자간 -4%. 로고 이미지는 만들지 않고 글자로만 쓴다. **노션 로고나 노션을 연상시키는 N 마크는 절대 쓰지 않는다.**
- 노션 스케일을 모바일 앱 크기로 줄였다. 큰 글자일수록 자간을 좁게 하는 노션 원칙은 그대로 따른다(한글은 라틴보다 조금 덜 좁힌다).

| 토큰 | size / line-height | weight | 자간 | 용도 |
|---|---|---|---|---|
| `wordmark` | 56 / 1.0 | 900 | -0.04em | 온보딩 워드마크 |
| `display` | 32 / 1.15 | 700 | -0.025em | 졸업식 타이틀, 온보딩 헤드라인 |
| `h1` | 26 / 1.25 | 700 | -0.02em | 화면 제목 |
| `h2` | 22 / 1.3 | 700 | -0.012em | 섹션 제목, 캐릭터 이름 |
| `h3` | 18 / 1.35 | 700 | -0.008em | 타일·카드 제목 |
| `title` | 17 / 1.4 | 600 | 0 | 리스트 항목, 시트 제목 |
| `body` | 16 / 1.5 | 400 | 0 | 본문 (입력칸은 반드시 16 이상 — iOS 확대 방지) |
| `body-sm` | 15 / 1.45 | 400 | 0 | 피드 메모, 밀도 높은 본문 |
| `button` | 16 / 1.5 | 600 | 0 | 버튼 글자 |
| `caption` | 14 / 1.43 | 400 | 0 | 날짜, 메타 (최소 14 — 13 이하는 쓰지 않음) |
| `eyebrow` | 12 / 1.33 | 600 | +0.01em | 단계 배지, 작은 라벨 (굵게만 사용) |
| `stat` | 36 / 1.0 | 700 | -0.03em | 진행률 %, 졸업 카드 숫자 |

- 본문은 400을 유지한다. 굵기 700은 제목에만 쓴다(노션 원칙).
- 모든 크기는 `rem`으로 작성한다(브라우저 글자 크기를 키우면 함께 커지도록).

## 3. 간격 · 레이아웃
- **기본 단위 8px** (노션): `xxs 4` · `xs 8` · `sm 12` · `md 16` · `lg 24` · `xl 28` · `xxl 32` · `3xl 48`
- 화면 좌우 여백 **16 (md)** · 카드 안쪽 여백: 전체 폭 카드 **24 (lg)**, 2열 타일 **16 (md)** · 타일 사이 간격 **12 (sm)** · 섹션 사이 간격 **32 (xxl)**
- 모바일 기준 폭 390px, 최소 지원 폭 320px. 2열 타일은 360px 미만에서 1열로 바뀐다.
- 고정된 하단 탭과 CTA가 콘텐츠를 가리지 않도록, 스크롤 영역 하단에 `탭 높이 + 24 + safe-area` 만큼 여백을 둔다.

## 4. 모서리 반경
노션 스케일을 기본으로 하고, 레퍼런스의 말랑한 인상을 위해 `2xl`, `3xl` 두 단계를 추가했다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `xs` | 4 | 작은 태그 |
| `sm` | 6 | 리스트 행 하이라이트 |
| `md` | 8 | 유틸리티 버튼, 입력칸 (입력칸은 절대 알약형으로 만들지 않는다 — 노션 원칙) |
| `lg` | 12 | 일반 카드, 피드 사진 |
| `xl` | 16 | 큰 카드, 이미지 영역 |
| `2xl` | **24** | 벤토 타일, 챌린지 카드 (레퍼런스 2) |
| `3xl` | **32** | 바텀시트·콘텐츠 시트의 상단 모서리 |
| `full` | 9999 | 주요/보조 버튼, 세그먼트, 하단 탭, 배지, 아바타 |

## 5. 높이감 (노션식: 아주 옅게)
| 레벨 | 값 | 용도 |
|---|---|---|
| 0 | `1px solid hairline`, 그림자 없음 | 기본 카드·타일 |
| 1 | `0 0.175px 1.04px rgba(0,0,0,.01), 0 0.8px 2.93px rgba(0,0,0,.02), 0 2px 7.85px rgba(0,0,0,.027), 0 4px 18px rgba(0,0,0,.04)` | 흰 보조 버튼, 떠 있는 타일, 말풍선 |
| 2 | 레벨 1 + `0 23px 52px rgba(0,0,0,.05)` | 하단 탭, 바텀시트, 토스트, 데모 컨트롤, 폰 프레임 |

진한 그림자는 쓰지 않는다. 입체감은 그림자 대신 **캐릭터의 그라데이션**이 만든다.

## 6. 캐릭터 스타일 (레퍼런스 1 기준 — v1 스티커 스타일에서 변경)
| 항목 | v1 (폐기) | **v2 (확정)** |
|---|---|---|
| 몸통 | 단색 + 남색 외곽선 | **외곽선 없음. 방사형 그라데이션 구체**: 하이라이트를 왼쪽 위 30% 지점에 두고, 가장자리는 살짝 흐리게(가우시안 블러 1.5~2) |
| 얼굴 선 | 얇은 남색 | **순검정 `#000`, 굵기 7~9 (viewBox 200 기준), 둥근 끝(round cap)** |
| 눈 | 작은 점 | 흰자(옅은 흰 광채) + 큰 검정 눈동자, 윙크·반달눈 등 표정 변형 |
| 머리·장식 | 모자 소품 | **검정 곡선 한 획**(앞머리, 컬, 더듬이) — 레퍼런스 1의 머리카락 선처럼 몸통 밖으로 튀어나와도 된다 |
| 그림자 | 회색 타원 | 바닥에 아주 옅은 타원(검정 6%) |

**캐릭터 구조 v3 (PRD v2 — 목표 캐릭터 + 부위 + 흔적)** ※ 성장 단계(알/아기/성장)는 폐기
- **템플릿 3종** = 몸통 모양 + 얼굴 배치 기본값: `round` 동글, `soft` 말랑(아래가 퍼진 물방울), `chubby` 통통(가로로 넓은 찹쌀떡)
- **부위 5개**(각각 독립된 SVG 그룹, 담당자 1명): `hair` 머리 선 · `eyeL` 왼쪽 눈 · `eyeR` 오른쪽 눈 · `cheek` 볼 · `mouth` 입. 몸통은 공동
- 부위 디자인은 템플릿마다 1종으로 고정한다(파츠를 고르는 단계는 없음)
- **그리기 상태** (부위마다):
  - 미완성: 점선(`stroke-dasharray 6 8`, `ink-3`) 실루엣
  - 진행 중: 점선 위로 실선이 `pathLength` 비율만큼 그려짐(인증 일수 ÷ 기간)
  - 몸통: 점선 외곽 + 그라데이션이 아래에서 위로 차오름(clipPath 높이 = 크루 인증률)
- **흔적 변형** (부위 그룹의 `transform`과 path 교체로 표현 — 부위 중심점 기준):
  - `scale`: 1 + 0.25(1회) … 최대 2.0
  - `rotate`: 2회부터 15°
  - `wavy`: 3회 이상이면 선을 물결 버전 path로 교체 → **부위마다 `normal`/`wavy` path 2벌 필요**
- **좋은 흔적**: 반짝이(별) 스티커, 정해진 7개 좌표에 순서대로 하나씩 추가
- **목표 vs 우리**: 같은 크기로 나란히 놓고, 목표는 흑백 점선, 우리는 컬러로 그린다
- 표정은 따로 두지 않는다(입도 부위다). 히어로의 대사는 말풍선이 맡는다

**굿즈 목업** (S8): 스티커(흰 테두리 다이컷), 아크릴 키링(투명 테두리 + 고리), 그립톡(원형), 미니 인형(그라데이션을 펠트 질감처럼 단순화). 모두 SVG/CSS로 만든 목업이며 사진은 쓰지 않는다.

**SVG 기술 규칙** (개발과 맞춘 약속)
- 모든 파일은 `viewBox="0 0 200 200"`을 쓴다. 몸통은 `cx 100, cy 110` 기준.
- 몸통 그라데이션 색은 CSS 변수로 받는다: `stop-color="var(--char-light)"`, `var(--char-base)`, `var(--char-deep)`.
  ↳ 이 방식은 `<img>`로 넣으면 동작하지 않는다. 개발은 SVG를 **인라인으로** 넣어야 한다.
- `id`(그라데이션, 필터)는 파일마다 접두사를 붙여서 서로 겹치지 않게 한다. 개발은 화면에 캐릭터가 여러 개 있을 때 인스턴스마다 고유 id를 붙인다.

## 8. 모션
- 기본 이징 `cubic-bezier(.2,.8,.2,1)`, 짧은 동작 150ms, 화면 전환 240ms
- 캐릭터 대기 동작: 3초 주기로 살짝 위아래로 움직이고(2px) 숨쉬기(scale 1↔1.02)
- 인증 시: 내 부위의 실선이 그려짐(stroke-dashoffset 700ms) → 몸통 색이 차오름 → 캐릭터 통통 튀기(spring)
- 흔적이 생길 때: 그 부위가 살짝 흔들린 뒤 새 크기·각도로 자리 잡음(400ms) + 히스토리 토스트
- 완성식: 목표 점선 위에 우리 캐릭터가 겹쳐졌다가 옆으로 나란히 갈라짐 → 흔적 카드가 차례로 올라옴
- **`prefers-reduced-motion: reduce`** 설정이면 모든 반복 동작과 큰 움직임을 끄고, 서서히 나타나기(opacity)만 남긴다

## 9. 접근성·UX 필수 규칙 (지침 요약 — 원문 `docs/references/ux-quality-guidelines.md`)
1. 글자 대비 4.5:1 이상, 큰 글자(24px 이상 또는 19px 굵게)와 UI 경계선은 3:1 이상 — 위 토큰으로 보장
2. 터치 영역 최소 44×44
3. **색만으로 상태를 표현하지 않는다**: 인증 여부, 기분, 진행 단계에는 모두 글자나 아이콘을 함께 둔다(예: 기분 = 표정 + "신나요"라는 글자)
4. 버튼 문구는 결과를 말한다: "확인" ✗ → "오늘 인증하기", "챌린지 시작하기", "다음 날로 넘기기", "처음 상태로 되돌리기"
5. 캐릭터 SVG에는 `role="img"`와 설명 라벨을 붙인다. 예: `aria-label="라임색 동글 캐릭터 뽀짝이, 성장 단계, 신난 표정"`. 장식용 요소는 `aria-hidden`
6. 인증 사진의 대체 텍스트는 "`{이름}`의 `{N}`일차 인증 사진: `{메모}`"
7. 모든 기능은 키보드로 사용할 수 있어야 한다. 바텀시트는 포커스를 시트 안에 가두고, Esc로 닫히며, 닫히면 포커스가 원래 위치로 돌아간다
8. 영향이 큰 행동은 확인을 받는다: '데모 초기화'는 무엇이 사라지는지 설명하는 확인 시트를 띄운다. 인증은 5초 동안 "되돌리기" 토스트를 보여준다
9. 상태 설계 필수: 빈 상태(도감 0개, 피드 0개), 오늘 이미 인증함(중복 인증 방지), 사진 용량 초과(자동으로 줄이고 안내), 지원하지 않는 파일 형식(원인과 해결 방법 안내), 저장 공간 가득 참
10. 브라우저 글자 크기를 200%로 키워도 글자가 잘리거나 겹치지 않는다. 고정 높이 대신 최소 높이(min-height)를 쓴다
